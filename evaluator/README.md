# Spike Test Evaluator

The Spike Test Evaluator is an automated benchmarking and evaluation suite for the Jetski AI agent. it's designed to measure the performance and adherence of the agent to modern web standards across various development scenarios.

## Features

- **Automated End-to-End Testing**: Uses Puppeteer to drive the Jetski Electron application, simulating real user interactions and prompts.
- **Scenario-Based Evaluation**: Includes predefined scenarios:
    - `greenfield`: Starting a project from scratch with modern features (e.g., polyfills, CSS View Timelines).
    - `brownfield`: Modifying existing projects.
    - `redfield`: Debugging and fixing broken projects.
- **Prompt Variations**: Supports both `specific` and `vague` prompts to test the agent's reasoning and clarification capabilities.
- **Guided vs. Unguided Comparison**: Compares agent performance with and without specific MCP (Model Context Protocol) servers.
- **Statistical Analysis**: Executes multiple runs (default 3) to calculate median pass rates, accounting for LLM variability.
- **Static Analysis Evaluation**: Uses Cheerio to inspect generated HTML, JS, and CSS against a set of expected outcomes.
- **Visual Dashboard**: A built-in web dashboard for exploring test results, chat logs, and performance metrics.

## Architecture

The suite follows a three-stage pipeline:

1.  **Setup (`run_suite.js`)**: Orchestrates the environment. It clears local agent state, backups artifacts, and prepares the target directories with initial project files and prompts.
2.  **Execution (`autorun.js`)**: Spawns the Jetski application, connects via CDP (Chrome DevTools Protocol), injects the user prompt into the agent interface, and waits for the task completion.
3.  **Evaluation (`evaluate.js`)**: Runs a suite of static analysis checks (located in `checks/`) against the files generated by the agent. It produces detailed Markdown and JSON reports.

## Directory Structure

```text
spike-runner/
├── checks/             # Logic for evaluating scenario success (Static analysis)
├── results/            # Output directory for test runs, logs, and reports
├── setup/              # Template files and prompts for each scenario
├── autorun.js          # Puppeteer script to automate the Jetski UI
├── config.js           # Centralized path and environment configuration
├── evaluate.js         # Report generator and evaluation runner
├── run_suite.js        # Main orchestrator for running the full test matrix
├── server.js           # Dashboard backend
└── dashboard.html      # Result visualization UI
```

## Getting Started

### Prerequisites

- [Jetski](https://github.com/google/jetski) installed.
- Node.js and npm.
- Environment configuration: Copy `.env.example` to `.env` and set `JETSKI_DIR` and `JETSKI_BIN`.

### Commands

**Run the full test suite and evaluate:**
```bash
npm run autorun
```
*This will execute the matrix of scenarios, save artifacts to `results/`, and generate a report.*

**Generate evaluation report for the latest run:**
```bash
npm run test
```

**View results in the dashboard:**
```bash
npm run dashboard
```
*Then open `http://localhost:3000` in your browser.*

## Evaluation Criteria

The evaluator checks for specific modern web features and best practices, such as:
- Use of `interestfor` instead of deprecated attributes.
- Implementation of JS polyfills for emerging features.
- Proper CSS feature detection and accessibility (e.g., `prefers-reduced-motion`).
- Correct implementation of View Timelines for animations.
