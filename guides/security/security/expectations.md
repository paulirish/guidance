- Server responses include the `Strict-Transport-Security` header (such as `max-age=31536000; includeSubDomains`) to enforce HTTPS connections.
- Client-side scripts render untrusted or dynamic text using safe DOM APIs (`textContent`, `innerText`, `createElement`, or `setHTML`) rather than dangerous sinks (`innerHTML`, `outerHTML`, `setHTMLUnsafe`, `document.write`, or `eval`).
- First-party session and authentication cookies use the `__Host-` prefix with `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/`, and no `Domain` attribute.
- Cookies set for third-party embedded iframe contexts use `SameSite=None; Secure; Partitioned`.
- Responses protect against clickjacking by setting both `X-Frame-Options: DENY` (or `SAMEORIGIN`) and the CSP `frame-ancestors 'none'` (or `'self'`) directive.
- Incoming `window` `message` event listeners validate `event.origin` against an explicit trusted origin allowlist.
- Outgoing `postMessage` calls specify an explicit target origin rather than wildcard `'*'`.
- Server responses configure a `Reporting-Endpoints` HTTP header and reference it via the `report-to` directive in `Content-Security-Policy` headers.
- The `Content-Security-Policy` header enforces a nonce-based or hash-based `script-src` with `'strict-dynamic'` and `'report-sample'`, `object-src 'none'`, and `base-uri 'none'`.
- The `Content-Security-Policy` header does not use broad scheme or domain allowlists (such as `https:` alone or `https://cdn.example.com` without `'strict-dynamic'`) as the primary `script-src` protection.
- The `Content-Security-Policy` header includes `require-trusted-types-for 'script'`, and any HTML DOM sink assignments are sanitized via `setHTML()` or a non-pass-through `trustedTypes.createPolicy(...)` policy.
- Document responses set `Cross-Origin-Opener-Policy: same-origin-allow-popups` (or `same-origin`).
- Server responses for app-internal documents, endpoints, and resources set `Cross-Origin-Resource-Policy: same-origin` (or `same-site`).
- Server-side Fetch Metadata protection inspects `Sec-Fetch-Site`, `Sec-Fetch-Mode`, and `Sec-Fetch-Dest` headers to reject unauthorized cross-site requests with HTTP status `403`, and includes `Vary: Sec-Fetch-Dest, Sec-Fetch-Mode, Sec-Fetch-Site`.
- Server responses set `X-Content-Type-Options: nosniff` alongside accurate `Content-Type` headers.
- Document responses set `Referrer-Policy: strict-origin-when-cross-origin`.
- Server responses set a restrictive `Permissions-Policy` header (such as `camera=(), geolocation=(), microphone=()`) to disable unused browser features.
- External versioned `<script>` and stylesheet tags include Subresource Integrity (`integrity="sha256-..."`, `sha384-...`, or `sha512-...`) paired with `crossorigin="anonymous"`.
- Cross-origin API endpoints validate the request `Origin` header against an explicit allowlist and return the matched trusted origin in `Access-Control-Allow-Origin` rather than wildcard `'*'`.
- Logout endpoint responses send the `Clear-Site-Data: "cookies", "storage", "cache"` header to terminate client state.
